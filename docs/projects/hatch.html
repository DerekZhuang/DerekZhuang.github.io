Hatch, a full-stack marketplace

A friend's startup MVP, July to August 2026. I took over development and wrote 91 of the 93 commits on main. github.com/tobyzijin925-web/projectHatch

Hatch is a two-sided marketplace where clients post tasks (“hatches”) and operators claim and complete them Fig. 2. My friend started the project and its first frontend. I took over development, built the backend, and added messaging and the full hatch lifecycle.

The server is Node.js on SQLite, using the built-in node:sqlite module with no external npm dependencies, and the schema has 14 tables with foreign keys. The hatch lifecycle (open, claimed, in progress, submitted, completed, plus disputed and cancelled) is enforced twice, by a database trigger and by the API's transition logic, so an illegal state change is rejected even if a bug gets past the API.

The intake assistant Fig. 1 calls DeepSeek or Groq from the server and never from the browser. It is rate-limited to 30 requests per 5 minutes per IP and falls back to a local rule-based brief generator when the provider is unreachable.

I also split an 8,861-line two-file frontend into 18 focused modules, one commit per module, leaving 533 lines in the original files.
